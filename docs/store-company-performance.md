# Store company Dashboard performance

Scope: active Store users can view Today and MTD for all company reporting locations, including sites they cannot edit. Existing exclude_from_reporting behavior remains. Dashboard loads a separate reporting-only location projection; AuthContext, Site Entry, role definitions and manager/admin routes are unchanged. Reporting market/site filters never populate operational selectors. Other Dashboard sections retain assigned-location scope. Admin and Area Manager screens retain their current location scope and raw-table read path.

Production evidence supplied for PR #16 shows authenticated location and Daily Log SELECT policies already allow company reporting. Raw budget_daily_entries uses an assignment-scoped ALL policy; broadening it would also broaden writes. Migration21 adds only dashboard_mtd_performance(uuid[],date,date), a STABLE SECURITY DEFINER counts-only read with an empty search_path, postgres ownership, authenticated execution and explicit active/non-deleted profile authorization. All three production roles remain supported. Store/Admin RPC reads can include company counts; Area Manager RPC results stay limited to explicit manager_locations mappings. No RLS, write helpers, profiles, assignments, audit grants/triggers or Edge Functions are changed. Nine output fields include location/date and washes/redemptions/tier/review counts, never cash/revenue/author/settings. Month bounds, ID limit and completed local-business-date cutoff remain.

Only Store Dashboard MTD opts into the RPC. All other consumers retain raw-table/RLS reads. Missing/denied RPC errors do not fall back to broader table access or partial Budget-site Daily Log totals. Current-day Today remains hourly Daily Logs; MTD uses the existing completed-day Budget-priority/non-Budget logic. The 60-second visible refresh remains.
